# Section 283 — Governed Read-Only KDS Ingredient Inference

## Behavior

Gelato Runtime Camera 1 can run a registered, approved, browser-specific ingredient ONNX model during a real active KDS ticket without starting a build session. MediaPipe remains the independently enabled two-hand tracker.

An authorized admin registers a browser_preview ONNX package in Glasses Vision Models with immutable HTTPS artifact, expected byte size, SHA-256, YOLO browser inference metadata/classes, and an active applicable rollout. Native AIR3 rollouts remain separate. No model is registered or activated automatically.

An authorized viewer clicks Start Camera then Load Read-Only Model. The server checks glasses.view and kds.view, scoped location/station, active browser rollout, canary or rollback selection, package status, ONNX platform and inference metadata. Paused or incompatible rollouts produce explicit hold results. No kitchen update or fake build-session ledger record is created.

The browser checks exact byte size and SHA-256, then uses the existing verified ONNX decoder. Inference is bounded to roughly 2.5 FPS, with no overlapping run, paused in background, and allowed only for active KDS items. Object detections are filtered to the next three unaccounted configured ingredients before entering Section 282 hand-held evidence tracking. Device and camera changes release the model; KDS item changes reject stale inference results.

No automatic KDS or checklist writes. Held ingredients still require three separate fresh detections and human review. Existing Camera Training and Vision Lab consent allow corrected, labeled samples to enter the offline training pipeline. This release does not invent an ingredient model.

## Administrator activation

1. Capture, label and explicitly approve ingredient samples using the existing supervised Vision Lab workflow.
2. Train and qualify a YOLO ingredient detector offline. Export ONNX and record exact artifact SHA-256 and byte size.
3. In Glasses Vision Models register an ONNX package with platform browser_preview, browser inference metadata, and no native SDK minimum. Configure a compatible baseline package as needed.
4. Create and activate an approved browser-preview rollout for the detector.
5. Start Camera 1, click Load Read-Only Model, and verify against actual active KDS tickets.

Acceptance requires JS and PHP Section 283 tests, earlier tracking/KDS regressions, full CI, SHA-256 deployment ZIP and interactive iPhone/Windows model signoff.
